# Markdown 文档规范

1. 先读取目标文件，并抽查同目录文档。
2. 按“概念 → 基础用法 → 实际场景 → 注意事项/小结”组织内容，简单主题可省略章节。
3. `#` 只用于文章标题；主要概念用 `##`，细分概念用 `###`，不跳级。
4. 术语、文件名、API、类名和函数名使用反引号。
5. 每个重要概念先用一两句话说明是什么、解决什么问题。
6. 示例使用带语言标记的代码围栏，优先 TypeScript；示例尽量小而完整。
7. 关键步骤添加简短中文注释，不给每一行都加注释；示例后说明结果或适用场景。
8. 中文与英文、数字之间适当留空格；避免重复、空泛和口语化表述。
9. 保留原文有效观点，修正明显术语、代码和格式问题；优先使用官方 API 名称。
10. 修改后用 `rg` 检查裸露代码、标题层级和拼写，并运行 `pnpm build` 验证渲染。
